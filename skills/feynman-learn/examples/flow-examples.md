# feynman-learn 示例

这些例子展示的是判断力，不是模板。**不要复用它们的句式、步骤数或篇章结构**——每个例子的组织方式都刻意不同，正是为了说明"结构由话题决定"。

## 概念题：双层解释

用户：我想学习"过拟合"。

处理判断：

直觉层用"学生死记练习题"的故事：见过的题满分，换个数字就不会——因为他记住的是题目本身，不是解题规律。

机制层揭开引擎盖：模型参数量相对数据量过大时，损失函数会驱动参数去拟合训练集中的噪声而非真实分布；表现为训练误差持续下降但验证误差回升。这也是为什么解法是早停、正则化、扩充数据——每一种都在"逼模型别去记题"。

类比失效点主动说明：学生"知道"自己在死记硬背，模型没有任何自省——它无法区分规律和噪声，这正是需要独立验证集的原因。这个失效点比类比本身更接近问题本质。

## 追问细节题：直接进机制层

用户（此前已听过"图书馆借书"类比）：我是开发者，KV cache 具体缓存的是什么？显存占用怎么算？

处理判断：

用户已有直觉，**不要再从故事讲起，不要重复类比**。直接给机制层的精确内容：缓存的是每层每个 token 的 Key 和 Value 张量；给出具体估算式（层数 × 2 × token 数 × 隐藏维度 × 精度字节数 × batch）；代入一个真实模型的参数算一遍数量级；顺带讲清这就是长上下文吃显存的原因，以及 GQA、PagedAttention 分别在省哪一项。

判断标准：回答要精确到用户可以直接拿去做容量规划。

## 流程/链路题：主线贯穿，双层随行

用户：给我讲讲 HTTPS 握手的完整过程。

处理判断：

链路题的骨架是"每一步之前是什么、之后变成什么、为什么少不了这一步"，故事服务于主线而不是反过来。

可以用"两个陌生人在监听的房间里约定暗号"建立直觉，但每个关键步骤都要落回真实机制：证书验证对应什么密码学操作、为什么非对称加密只用来交换密钥而不加密数据（性能，量级差三个数量级）、会话密钥之后的通信为什么换对称加密。

塞不进故事的要点（如证书链、CA 信任锚）直接讲，不硬套进"房间暗号"里。

## 纠错题：修最关键的断链

用户：我的理解是 RLHF 就是人类把最终答案都写好。哪里不对？

处理判断：

先复述用户当前的图景，找到最关键的错误链接：人类提供的是偏好信号（这个回答比那个好），不是答案本身；模型从比较中学习，而非从范本中抄写。

只修这一条断链，配一个承载因果的类比（教练不替学员打球，只指出哪一杆更好），然后在机制层说清 reward model 的角色。不展开成 RLHF 全景课——用户问的是纠错，不是综述。
